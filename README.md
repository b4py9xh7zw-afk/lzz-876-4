# 企业内控合规测评平台

面向法务 / 审计部门的红线学习与测评系统，核心目标不是"统计通过人数"，而是能
**逐人证明：谁、在什么岗位、什么时候学过、考了多少分、是否签署确认**，并且全部记录
防篡改、可独立核验。

## 功能与角色

| 角色 | 能做什么 |
|---|---|
| 员工 | 查看本人任务 → 学习材料（满 30 秒才能开卷）→ 答题（最多 3 次）→ 达标后电子签署《学习确认与合规承诺》→ 查看/导出个人证据 |
| 法务 / 审计（发布者） | 创建反舞弊/数据安全/采购红线测验、编辑题目、按全员/部门/风险等级/指定人员开放任务、查看**逐人花名册**、导出 CSV、执行证据链完整性校验 |
| 管理员 | 维护人员账号、部门岗位、**岗位风险等级**（决定个人及格线） |

- 及格线分岗位：普通 60 / 关键 80 / **高风险 90（硬门槛，未达标在花名册逐人标红，不能靠签署绕过）**。
- 题目在开卷时整体快照进答卷，之后改题不影响历史记录。
- 服务端独立判分；多选题少选/错选不得分。

## 如何证明"谁在什么时候学过"（不是只看通过人数）

1. **逐人花名册**：每个开放任务对应受众中每个人一行——工号、姓名、部门岗位、风险等级、
   个人门槛、状态、提交次数、最好成绩、交卷时间、签署时间、个人证据链接；可导出 CSV。
2. **追加式哈希证据链**（evidence_events 表）：学习打开、开卷、交卷判分、签署、
   发布/关闭、人员变更全部落事件；每行哈希包含前一行哈希（SHA-256）：

   event_hash = sha256(seq | type | actor | refs | canonical(payload) | created_at | prev_hash)

3. **关键事件内嵌快照并交叉校验**：
   - quiz.published：固化全部题面+答案与摘要，事后改题库会导致校验失败；
   - attempt.submitted：固化题目快照、员工身份、作答、独立判分明细——事后改分会被重新判分比对发现；
   - confirmation.signed：固化承诺全文、签名文字、工号、成绩、签署时间的哈希——改签名即断链。
4. **公开核验页 /verify**：粘贴任一 64 位事件哈希，系统从链首重算并交叉比对，
   给出"核验通过 / 失败原因"。证据包可导出 JSON、打印 PDF。
5. 每条记录含行为人 IP 与 User-Agent、UTC 时间戳。

> 诚实的边界：哈希链防的是**事后篡改与抵赖**（改库即校验失败）；若要防 DBA
> 级威胁，可把每日链尾哈希外发（WORM 存储/区块链/定时邮件），/verify 逻辑无需改动。

```bash

python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
# 打开 http://localhost:8000 ，首次启动自动建表并写入演示数据
```

## 目录结构

```
app/
  main.py              入口与签名 Cookie 会话中间件
  models.py            User/Quiz/Question/Assignment/Attempt/Confirmation/EvidenceEvent
  evidence.py          哈希链、快照、独立判分、签名哈希、全链校验（平台核心）
  services.py          受众匹配、岗位门槛、逐人状态、花名册
  routes_auth.py       登录/登出/改密（PBKDF2-SHA256）
  routes_employee.py   学习→开卷→交卷→签署→证据页/证据包
  routes_publisher.py  题库、发布、开放任务、花名册 CSV、证据链审计页
  routes_admin.py      人员与风险岗位管理（变更留痕）
  seed.py              演示账号与三套红线测验
templates/ static/     服务端渲染页面（可打印证据页）
tests/                 端到端流程与篡改检测
```
